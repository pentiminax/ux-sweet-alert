# Themes & Styling

UX SweetAlert passes theme and styling data directly into the serialized alert payload. That keeps
your Symfony code in charge of the visual intent while SweetAlert2 handles the rendering.

## Theme enum support

The `Theme` enum includes:

- `Auto`, `Light`, `Dark`, `Borderless`, `Minimal`, `EmbedIframe`
- `Bootstrap4`, `Bootstrap4Light`, `Bootstrap4Dark`
- `Bootstrap5`, `Bootstrap5Light`, `Bootstrap5Dark`
- `MaterialUI`, `MaterialUILight`, `MaterialUIDark`
- `Bulma`, `BulmaLight`, `BulmaDark`

## Applying a theme

```php
use Pentiminax\UX\SweetAlert\Enum\Theme;

$alertManager
    ->success('Saved')
    ->theme(Theme::Bootstrap5Dark);
```

## Loading the matching CSS

The package metadata exposes SweetAlert2 theme files in `assets/package.json`, but the optional
theme styles are not auto-enabled by default. If you want a framework theme, make sure the matching
SweetAlert2 CSS is imported by your asset pipeline.

## Fine-grained styling

The `Alert` object lets you control button colors and CSS hooks:

```php
$alertManager
    ->question('Archive item?')
    ->confirmButtonColor('#ff6b4f')
    ->cancelButtonColor('#2f4858')
    ->denyButtonColor('#f4b400')
    ->theme(Theme::Dark);
```

You can also pass a `customClass` array when creating alerts through the manager helpers.

## Popup size and colors

```php
$alertManager
    ->info('Welcome back')
    ->width('32rem')          // int (px) or any CSS length
    ->padding('3em')
    ->background('#fff url(/images/trees.png)')
    ->color('#716add');
```

These keys are only sent when set, so SweetAlert2 and theme defaults apply otherwise.

## Show and hide animations

`showClass()` and `hideClass()` set the CSS classes put on the popup when it opens and closes. Pass
an `Animation` preset or any class string:

```php
use Pentiminax\UX\SweetAlert\Enum\Animation;

$alertManager
    ->success('Saved')
    ->showClass(Animation::FadeInUp)
    ->hideClass(Animation::FadeOutDown);

// Serialized as {"showClass": {"popup": "animate__animated animate__fadeInUp animate__faster"}, ...}
```

Presets: `FadeIn`, `FadeOut`, `FadeInUp`, `FadeOutDown`, `FadeInDown`, `FadeOutUp`, `ZoomIn`, `ZoomOut`.

<Aside type="caution">
  The presets are [Animate.css](https://animate.style/) classes. The bundle does not ship Animate.css:
  load it yourself (e.g. `importmap:require animate.css` or a CDN link), otherwise the popup appears
  without animation. Only the `popup` classes are set; SweetAlert2 keeps its default backdrop and
  icon classes. `withoutAnimation()` disables SweetAlert2 animations and overrides `showClass()` /
  `hideClass()`.
</Aside>

## Content-level styling options

Beyond the theme name, the alert model supports:

- `html(...)` for rich HTML content
- `setFooter(...)` for footer text or markup
- `setImageUrl(...)`, `setImageAlt(...)`, `setImageHeight(...)`, and `setImageWidth(...)`
- `setDraggable(...)` and `setTopLayer(...)`

## Styling lifecycle events

The frontend controller emits two useful browser events around every modal render:

- `sweetalert:before-fire`
- `sweetalert:after-fire`

Both expose the SweetAlert options object, making them useful when your application needs to add
cross-cutting frontend tweaks without changing the PHP API.

<Aside type="note">
  Prefer themes and `customClass` for structural styling. Use the browser events only when a visual
  adjustment truly belongs on the frontend side.
</Aside>
